# 接入现有同步与回退

> 本项目在云端容器中开发，**没有访问过你的 Mac**。下面所有关于你本机脚本、LaunchAgent 与历史的判断，都需要你在本机运行“接入检查”确认。

## 0. 先决条件

- macOS 14，Apple Silicon；
- `/opt/homebrew/bin/rclone`（v1.75.2 已验证支持所需的 RC 接口与 `--rc-htpasswd`）；
- 现有文件保持不变：`sync.py`、两个 LaunchAgent、`state/*/status.json`、`logs/*.log`、bisync 历史（默认在 `~/Library/Caches/rclone/bisync`，或脚本中 `--workdir` 指定的位置）。

## 1. 安装 App，先观察

1. 构建或下载 `RcloneBar.app`，放到“应用程序”并打开（菜单栏出现图标，Dock 中没有）。
2. 此时为**观察模式**：不修改任何东西，只读取进程、状态文件、日志与 bisync listing。
   - “立即同步”= `launchctl kickstart gui/<uid>/com.zhuke.rclone-bisync.<任务>`，不会重复启动正在运行的任务；
   - “安全结束本轮”= 向该组 `rclone bisync` 进程发送 SIGINT；
   - 当前已经在运行、没有开启 RC 的 rclone 进程**不会被重启**；本轮界面显示“本轮未开启实时接口”，用日志与状态文件补充信息。

## 2. 接入检查（只读）

“设置 → 后台服务 → 接入检查”，或在终端：

```bash
/Applications/RcloneBar.app/Contents/MacOS/rclonebar-agent inspect
```

报告包括：rclone 版本与 RC 参数支持、`sync.py` 中出现的参数（`--resync`、`--force`、`--recover`、`--resilient`、`--check-access`、`--max-delete`、`--backup-dir*`、`--conflict-*`、`--workdir` 等）、两个 LaunchAgent 的命令/调度/环境变量名称（不显示值）、launchd 状态、正在运行的 bisync、bisync 历史位置与锁文件、状态文件摘要与日志末尾（已脱敏）。

重点看“注意事项”：

| 提示 | 含义与建议 |
| --- | --- |
| 未发现 `--recover` | “安全结束本轮”后下一轮可能需要人工处理。建议在 `sync.py` 中加入 `--resilient --recover`（自行修改脚本，RcloneBar 不改脚本）。 |
| 出现 `--resync` / `--force` | 确认脚本不会在普通运行中自动使用它们。RcloneBar 自身从不使用。 |
| `env=` 自定义环境 | 若子进程没有继承父进程环境，RC 无法通过环境变量开启；界面会退回读取日志。可改为 `env={**os.environ, ...}`。 |
| 未找到 bisync 历史 | 结果判定只能依赖退出码与日志；**不要**因此执行 `--resync`。 |
| 存在锁文件但没有进程 | 上次可能异常退出；bisync 会按 `--max-lock` 处理，RcloneBar 不会删除它。 |

## 3. 接管（安全交接）

“设置 → 后台服务 → 接管（安全交接）…”，或 `rclonebar-agent install`（可先加 `--dry-run` 演练）。

前提：两组都**没有**正在运行的同步；否则会拒绝接管，等本轮结束再试（不会为了开启 RC 强行重启同步）。

接管做的事情：

1. **备份**到 `~/Library/Application Support/RcloneBar/backups/handoff-<时间>/`：两个 LaunchAgent plist、`sync.py`、两个 `status.json`。bisync 历史、`RCLONE_TEST` 访问检查标记、冲突副本与备份目录**不复制也不改动**。
2. 生成 RC 认证：`rc/credential.json`（0600，明文仅供 App 读取）与 `rc/htpasswd`（0600，只含 `{SHA}` 哈希）。
3. 写入 `jobs.json`（两组任务定义、发现的 bisync 工作目录）与 `settings.json`（同步间隔沿用原 `StartInterval`，300 秒 → 5 分钟）。
4. 改写两个原 LaunchAgent：
   - 删除 `StartInterval`、`StartCalendarInterval`、`KeepAlive`、`WatchPaths`、`QueueDirectories`、`StartOnMount`，`RunAtLoad` 设为 false；
   - `EnvironmentVariables` 中加入 `RCLONE_RC=true`、`RCLONE_RC_ADDR=127.0.0.1:55721`（项目为 55722）、`RCLONE_RC_HTPASSWD=<htpasswd 路径>`，以及设置中的 `RCLONE_TRANSFERS`、`RCLONE_BWLIMIT`（如有）；
   - `ProgramArguments`、`WorkingDirectory`、`StandardOutPath` 等其余内容保持不变；
   - 改写前再次确认该任务空闲，然后 `bootout` + `bootstrap` 重新加载。任何一步失败会自动恢复已改写的 plist。
5. 安装后台服务：复制 `rclonebar-agent` 到 `RcloneBar/bin/`，写入 `~/Library/LaunchAgents/com.zhuke.rclonebar.agent.plist`（`RunAtLoad`、异常退出自动重启）并加载。
6. 写入 `install.json`（回退所需信息）。

接管后：

- 只有 `com.zhuke.rclonebar.agent` 会定时启动同步；原 LaunchAgent 只在被它 kickstart 时运行；
- 下一轮开始 rclone 带 RC 运行，界面显示实时进度；
- 并发数在下一轮生效；限速在运行中约 5 秒内通过 `core/bwlimit` 生效；
- 间隔修改立即重新计算下次运行时间；暂停只影响新的一轮。

## 4. 回退

“设置 → 后台服务 → 回退到原 LaunchAgent…”，或：

```bash
~/Library/Application\ Support/RcloneBar/bin/rclonebar-agent uninstall
```

回退会：停止并移除 `com.zhuke.rclonebar.agent`；用 `handoff-*` 中的原始文件**逐字节**恢复两个 LaunchAgent 并重新加载（恢复原有每 300 秒的调度）；把回退前的文件留在 `backups/rollback-<时间>/`。设置与运行记录保留。

如果 App 已无法打开，也可手动回退：

```bash
UID_=$(id -u)
launchctl bootout gui/$UID_/com.zhuke.rclonebar.agent
rm ~/Library/LaunchAgents/com.zhuke.rclonebar.agent.plist
B=$(ls -d ~/Library/Application\ Support/RcloneBar/backups/handoff-* | tail -1)
for j in vault projects; do
  launchctl bootout gui/$UID_/com.zhuke.rclone-bisync.$j
  cp "$B/LaunchAgents/com.zhuke.rclone-bisync.$j.plist" ~/Library/LaunchAgents/
  launchctl bootstrap gui/$UID_ ~/Library/LaunchAgents/com.zhuke.rclone-bisync.$j.plist
done
rm ~/Library/Application\ Support/RcloneBar/install.json
```

## 5. 需要你在本机完成的授权步骤

1. **打开未公证的 App**：ad-hoc 签名，首次需右键 →“打开”，或 `xattr -dr com.apple.quarantine /Applications/RcloneBar.app`。
2. **后台项目提示**：接管时 macOS 会提示“已添加后台项目”。请在“系统设置 → 通用 → 登录项 → 允许在后台”中保持 `rclonebar-agent` 与原 `rclone-bisync` 项为开启。
3. **文件访问**：同步仍由原 LaunchAgent 启动的解释器执行，原先授予的“完全磁盘访问权限”继续有效，通常无需新授权。若接管后日志出现 `operation not permitted`，请在“隐私与安全性 → 完全磁盘访问权限”中确认原脚本解释器（如 `/opt/homebrew/bin/python3` 或 plist 中的第一个程序）已勾选。后台服务本身只读写 `~/Library/Application Support`，不访问“文稿”。
   - “接入检查”会确认两个本地目录是否存在，系统可能询问是否允许 RcloneBar 访问“文稿”文件夹。允许或拒绝都不影响同步本身（拒绝时报告里会显示“本地目录不存在”的误报）。
4. **通知**：首次需要发送通知时系统会询问，选择“允许”。
5. **登录后打开界面**（可选）：设置 → 同步 → “登录后自动打开 RcloneBar 界面”。后台调度不依赖这个开关。
6. **OneDrive 重新授权**（仅在提示需要时）：`rclone config reconnect onedrive:`。RcloneBar 不读取、不显示 OAuth 令牌。

## 6. 文件一览

| 路径 | 用途 |
| --- | --- |
| `~/Library/Application Support/RcloneBar/settings.json` | 设置（App 写，后台服务读） |
| `…/RcloneBar/jobs.json` | 任务定义 |
| `…/RcloneBar/agent-state.json` | 后台服务状态（约每秒更新） |
| `…/RcloneBar/runs.jsonl` | 运行记录（自动截断） |
| `…/RcloneBar/control/` | App → 后台服务命令（一次性文件） |
| `…/RcloneBar/logs/agent.log` | 后台服务日志（1 MB 滚动） |
| `…/RcloneBar/rc/` | RC 认证（0700 目录，0600 文件） |
| `…/RcloneBar/backups/` | 接管 / 回退前的备份 |
